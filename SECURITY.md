# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| 0.1.x   | ✅        |

## Reporting a Vulnerability

If you discover a security vulnerability in this project, **please do not open a
public GitHub issue**. Instead, report it privately to the maintainer so it can
be addressed before public disclosure.

### How to Report

Send a detailed report to:

**Jeff Li** — li_jeff@yahoo.com

Please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce the issue
- Any relevant code snippets, logs, or screenshots
- Your suggested fix or mitigation (if any)

### Response Timeline

| Step                         | Target time     |
|------------------------------|-----------------|
| Acknowledgement of report    | Within 5 days   |
| Initial assessment           | Within 10 days  |
| Fix or mitigation released   | Within 30 days  |

We appreciate responsible disclosure and will credit reporters in the release notes
(unless you prefer to remain anonymous).

## Security Best Practices for Contributors

- Do not commit credentials, secrets, or tokens.
- Use dependabot or equivalent to keep dependencies up to date.
- Review code changes for injection vulnerabilities or unsafe deserialization.
